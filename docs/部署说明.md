# 本地与服务器部署

本文面向部署管理员，用于启动带账户和旅行助手的北行路书、配置公网入口、更新版本及备份服务端数据。

1. 使用当前源码，Node.js 22.13+ 和 Python 3.11+，执行 `npm ci`、`python3 -m venv .venv`、`.venv/bin/pip install -r agent/requirements.txt`。
2. 将 `.env.example` 复制为 `.env.local`，填写高德 Web端 Key、安全密钥，以及独立管理账号 `ADMIN_USERNAME`、`ADMIN_PASSWORD`（至少 10 个字符），可选 `ADMIN_NAME`。
3. 本机开发使用 `npm run dev`；生产运行 `npm run build` 后 `npm start`。
4. 对外部署配置 HTTPS 反向代理，将 `PUBLIC_ORIGIN` 设置为实际 HTTPS origin，按需设置 `HOST=0.0.0.0` 和 `PORT`。配置高德控制台域名。
5. 把 `ACCOUNTS_DB_PATH` 指向持久化目录，禁止放在静态资源目录。使用环境配置中的管理账号登录，分别邀请自己和旅伴注册普通成员账号；日常使用路书时登录各自的成员账号。管理员配置修改后重启服务即可生效，密码变化会使旧管理登录失效。
6. 管理员登录后在“旅行助手”配置模型地址、模型名、API Key。也可在环境中设置 `AGENT_BASE_URL`、`AGENT_MODEL`、`AGENT_API_KEY`。网页保存配置后下一次回复生效，环境配置变更需要重启。
7. 升级时保留整个 `.runtime` 和环境配置。助手的聊天、记忆、运行检查点、地点笔记和 MCP 配置位于 `AGENT_DATA_DIR`（默认 `.runtime/agent`）。停服务后备份整个目录，避免漏掉 SQLite 的 WAL 文件。Docker 镜像包含 Python 运行环境，持久化卷挂载 `/app/.runtime`，详细命令见《账户系统》。

反向代理需允许 `/api/agent/events` 的 SSE 长连接：关闭该路径的响应缓冲，将读取超时设为至少 60 秒（服务端每 15 秒发送心跳）。助手仅在 Node 后面运行，Agent Python 使用本地管道；MCP 连接由独立网关进程或容器处理，不开放公网端口。独立容器部署见《旅行助手》的 MCP 微服务部署。运行时需要能访问模型及所配置 MCP 服务。当前设计用于单个 Node 实例；不要让多个服务实例同时读写同一助手目录。

语音输入需要 HTTPS 和麦克风权限，服务器还需可访问 `https://openspeech.bytedance.com`。在管理页面配置火山语音 API Key，或使用 `VOLC_SPEECH_API_KEY`；旧版控制台可使用 `VOLC_SPEECH_APP_ID` 与 `VOLC_SPEECH_ACCESS_TOKEN`。需开通 `volc.bigasr.auc_turbo` 资源。反向代理对 `/api/agent/speech` 允许至少 2 MB 请求体、至少 65 秒读取超时；该接口禁止缓存，音频不落盘。环境变量变更后重启，页面配置保存后即时生效。

必须保留 Node 服务与 `agent/`、`data/roadbook.json`：账户、助手接口和高德安全代理与页面同源。纯静态托管或旧版 `northbound-roadbook-0.3.3-amap.zip` 不包含本版完整功能。

路线与帖子仍是固定内容。账户数据保存在服务端 SQLite 中；账户接口不会进入 PWA 缓存，页面打开时需要联网验证登录。用户头像等私人资料不写入静态构建。备份、恢复、会话及权限边界见 [账户系统](账户系统.md)，高德配置见 [高德地图配置](高德地图配置.md)。

## 腾讯云服务器

目标服务器为 `ubuntu@140.143.248.244`，当前访问入口为 [https://140.143.248.244:8443](https://140.143.248.244:8443)，域名 `roadbook.heyjianhang.top` 待解除腾讯云拦截后启用。公网入口遵循服务器 `/home/ubuntu/NGINX.md`，由宿主机 Nginx 统一提供。

| 项目           | 位置或名称                                                         |
| -------------- | ------------------------------------------------------------------ |
| 部署根目录     | `/home/ubuntu/code/northbound-roadbook`                            |
| 版本目录       | `releases/<版本号>`                                                |

| 路书服务       | `127.0.0.1:4173`，仅回环访问                                       |
| MCP 网关       | 容器内网 4180，无宿主机端口                                        |
| Nginx 配置源   | `/home/ubuntu/nginx/sites-available/roadbook.heyjianhang.top.conf` |
| Nginx 发布副本 | `/etc/nginx/conf.d/roadbook.heyjianhang.top.conf`                  |

首次部署使用空数据库和服务器新生成的管理员凭据。模型、MCP、语音和高德密钥需在服务器重新配置。管理员只负责邀请成员与配置服务，日常使用需注册普通成员账户。

构建可通过 `ROADBOOK_DEBIAN_MIRROR` 和 `ROADBOOK_PYPI_INDEX_URL` 设置软件源，未设置时使用 Debian / PyPI 默认源。本服务器分别使用 `http://mirrors.cloud.tencent.com` 和 `https://mirrors.cloud.tencent.com/pypi/simple`，避免跨境下载缓慢；保留 Debian 签名校验和项目锁定的依赖版本。软件源用法见[腾讯云官方说明](https://cloud.tencent.cn/document/product/213/8623)。

### IP HTTPS 入口

公网 TCP 8443 由 Nginx 终止 TLS，再代理至 `127.0.0.1:4173`。`4173` 是内部 HTTP 端口，不作为公网入口。访问 `http://140.143.248.244/` 会跳转到 IP 的 HTTPS 地址，80 端口同时保留证书自动续期需要的 HTTP-01 挑战路径。安全组需允许公网 TCP 80 和 8443。

`shared/.env` 中的 `PUBLIC_ORIGIN` 为 `https://140.143.248.244:8443`。账户使用安全 Cookie，登录凭据和数据库沿用已有配置。IP 与域名属于不同浏览器来源，切换入口后需要重新登录和安装 PWA。

- Nginx 源文件：`/home/ubuntu/nginx/sites-available/140.143.248.244.conf`。
- 发布副本：`/etc/nginx/conf.d/140.143.248.244.conf`。
- 代理模板：`deploy/nginx/roadbook-ip.conf.template`。
- IP 证书：`/etc/letsencrypt-roadbook-ip/live/roadbook-ip/`。
- 续期脚本：`/usr/local/sbin/roadbook-ip-renew`，源文件为 `deploy/roadbook-ip-renew.sh`。
- 独立定时任务：`roadbook-ip-renew.timer`，每日两次检查，有随机延迟，成功续期后才检查并重载 Nginx。

IP 证书采用 Let's Encrypt 短期证书，由固定摘要的官方 Certbot 5.8.0 容器管理。证书目录与原有 Certbot 分开，原站点继续使用原有 `certbot.timer`。不要停用 IP 证书续期任务或封闭其 80 端口挑战路径。[IP 证书说明](https://letsencrypt.org/2026/03/11/shorter-certs-certbot)

检查状态与演练续期：

```sh
systemctl status roadbook-ip-renew.timer
sudo journalctl -u roadbook-ip-renew.service -n 30
sudo /usr/local/sbin/roadbook-ip-renew --dry-run --run-deploy-hooks
```

2026-09-10 已完成公网 TLS、首页、账户接口和续期演练；身份校验使用实际 HTTPS 来源，模型和语音是否可用仍取决于管理员配置。

### 切换到域名 HTTPS

2026-09-10 验证时，域名的本机 HTTP 挑战路径返回 200，公网请求被腾讯云转到 DNSPod 域名拦截页，Let's Encrypt 的 HTTP-01 签发也因此失败。域名入口尚未完成公网验收。该域名当前已发布配置只提供证书挑战路径，其余路径返回 503；正式代理模板保存在 `deploy/nginx/roadbook.conf.template`。

在腾讯云解除域名拦截后，先从服务器之外确认挑战路径不再跳往拦截页，再在服务器执行：

```sh
cd /home/ubuntu/code/northbound-roadbook/current
bash scripts/enable-server-https.sh
sudo certbot renew --cert-name roadbook.heyjianhang.top --dry-run
systemctl is-active certbot.timer
```

脚本先申请证书，从 Certbot 实际续期配置读取证书路径，再备份、渲染、发布单个域名配置，检查成功后平滑重载。语法检查或重载失败会恢复该域名的原配置。已有续期部署钩子位于 `/etc/letsencrypt/renewal-hooks/deploy/reload-nginx.sh`，无需重复创建。

证书与代理启用后，再把 `shared/.env` 的 `PUBLIC_ORIGIN` 改为 `https://roadbook.heyjianhang.top`，按下方日常操作重建 `roadbook` 容器，并改用域名登录。停用 IP 入口时，按服务器规范备份并撤下 IP 的 Nginx 配置，再停用对应续期定时任务；不要影响其他站点的配置与续期。

外部验证首页、管理员登录、成员邀请、SSE 和语音上传后，更新服务器 `/home/ubuntu/NGINX.md` 台账并在 `/home/ubuntu/nginx/records/` 留下记录。模板对 API 关闭响应缓冲和缓存，读取超时 300 秒，请求体上限 8 MB，支持头像及语音上传；真实 IP 与转发协议由入口覆盖。

### 日常操作

```sh
cd /home/ubuntu/code/northbound-roadbook/current
docker compose -p northbound-roadbook --env-file /home/ubuntu/code/northbound-roadbook/shared/.env ps
```

查看初始管理员信息，在 SSH 会话中执行 `cat /home/ubuntu/code/northbound-roadbook/shared/initial-admin.txt`。修改管理员密码或环境变量后，执行以下命令重建应用容器，使环境配置生效：

```sh
docker compose -p northbound-roadbook --env-file /home/ubuntu/code/northbound-roadbook/shared/.env up -d --force-recreate roadbook
```

更改 `MCP_GATEWAY_TOKEN` 时需同时重新创建 `roadbook` 和 `mcp-gateway`。网页保存的助手配置无需重建容器。

更新版本时，把源码上传到新的 `releases/<版本号>`，保留 `shared/.env` 与数据卷；设置 `ROADBOOK_RELEASE` 为新版本号，`ROADBOOK_ENV_FILE` 为私有环境文件绝对路径。使用相同 Compose 项目名构建、启动，确认两个容器健康后更新 `current`。镜像名称为 `northbound-roadbook/roadbook:<版本号>` 和 `northbound-roadbook/mcp-gateway:<版本号>`，保留上一个版本以便回退。

升级前短暂停止 `roadbook`，备份整个持久化卷与 `shared/.env` 到受限目录，再恢复服务。不要只复制正在使用的 SQLite 主文件。回退时先停止应用，按需恢复配套数据备份和旧版本环境配置，再启动旧镜像。禁止使用 `docker compose down -v`，该命令会删除业务数据卷。只操作本项目，勿重启宿主机 Docker 或其他项目容器。
