模式：修订并实现。

## 安装入口修订 · 2026-09-10

成员账户页在资料表单之前加入 `{InstallCard}`，复用现有 Card、Button、Alert 和 Spinner，不调整全局主题。项目查询已执行 summary、routes --query account、shell、components --query install；shadcn info 确认 base-nova / Base UI，官方 @shadcn registry 已查询 dialog，button/card/dialog 官方文档已核对。现有 PwaProvider 持有浏览器安装事件。

```text
账户页
┌──────────────────────────────────────────┐
│ [CardHeader] 安装北行路书                 │
│ [CardDescription] 从主屏幕打开路书         │
│ [CardContent] 安装指引（按需展开）         │
│ [CardFooter] *[Button 安装 / 查看步骤]     │
└──────────────────────────────────────────┘
原有个人资料与修改密码
```

安卓和桌面在收到 beforeinstallprompt 时由按钮直接调用系统安装提示；没有事件时展开浏览器菜单安装指引。iPhone/iPad 展开 Safari「共享 → 添加到主屏幕 → 添加」步骤；iOS 26 若显示「作为网页 App 打开」需保持开启。当前以独立应用模式打开时显示已安装状态，不重复触发。系统弹窗等待中按钮禁用并显示进度，取消不显示安装成功，异常通过 Alert 反馈并可重新查看步骤。桌面沿用账户页宽度，手机按钮占满可用宽度，所有内容位于现有底部导航留白之上。

安装行为仅使用 PwaProvider 和浏览器安装事件，无新增后端接口。页面可见、从外部 App 返回和 pageshow 时刷新安装状态，并节流检查 Service Worker 更新；不重写当前地点、日期和返回路线参数。

依据：[Apple 安装说明](https://support.apple.com/zh-cn/guide/iphone/iphea86e5236/ios)、[MDN 安装事件](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeinstallprompt_event)。iPhone 无网页可直接触发的系统安装提示，最终添加动作由用户在系统菜单完成。

## 2. 页面目标

成员完成登录、注册、编辑资料和修改密码。管理员进入独立的成员管理页；普通成员登录或邀请注册成功后进入每日路书，保留选中的日期并清除旧页面及地点参数，个人账户入口为 `?view=account`。有效会话刷新和重新检查不触发跳转。管理员由环境配置维护，自己和旅伴均邀请注册为普通成员。没有公开的自由注册入口。

## 3. 信息优先级

登录和邀请注册在卡片顶部固定显示品牌图标和名称，任务标题仅供读屏使用；注册不显示额外的欢迎标题和介绍。重置密码保留任务标题和说明。账户、密码等表单字段在中间滚动，底部仅保留提交按钮及操作反馈。头像使用项目已有的 React Avatar 组合，通过点击头像或上传文字选择图片，选择后可预览、更换或移除。普通成员账户页显示本人资料和安全设置；管理员页面先说明邀请注册流程，再显示邀请和成员列表，不渲染路书导航。

## 4. 组件清单

Button、Input、Field/FieldGroup、Card、Alert、Avatar、Badge、Skeleton、Empty、AlertDialog 均为已安装组件，来自 components/ui；已查询对应官方文档。AccountProvider、AuthForm、AccountPage、AdminPage、MemberManagement 为本功能组合的业务组件。

## 6. 交互与状态

| 行为或状态 | 呈现和处理 |
|---|---|
| 正在验证登录或加载成员 | Skeleton |
| 无网络 | Alert 与重试，不能将未验证身份视为有效登录 |
| 邀请无效、过期、已使用 | Alert；注册表单不可提交，提示重新获取链接 |
| 表单提交 | 字段和提交按钮禁用，显示 Spinner；保留失败输入 |
| 头像处理 | 压缩期间禁用提交，失败显示 Alert |
| 保存成功 | 可感知的成功反馈 |
| 无邀请 | Empty，说明如何创建 |
| 普通成员 | 不渲染管理区，服务端同时拒绝越权 |
| 管理员 | 只渲染管理页；高德接口、个人资料和密码修改接口拒绝管理身份 |
| 管理员未配置 | 登录表单显示提示，已有普通成员仍可登录 |
| 无成员 | Empty，提示分别为自己和旅伴生成邀请 |
| 停用成员 | AlertDialog 确认；失败保留上下文；成功刷新列表 |
| 邀请和重置链接 | 从 URL fragment 读取令牌，支持刷新继续填写；成功消费后清除令牌 |

## 7. 响应式与可访问性

账户卡片在可用屏幕高度内居中并略向下偏移，上下留白随高度变化并计入安全区域。卡片宽度限制在 420px 内，高度不超过 720px 和动态视口减去留白中的较小值。顶部品牌和底部按钮保持可见，中间字段超出时独立滚动，短屏进一步减小留白。表单采用紧凑间距，同时保留至少 44px 的输入和按钮触控高度。输入字段和提交按钮仍属于同一个原生表单，保留回车提交、必填验证和键盘焦点移动。桌面个人资料与修改密码并排，手机顺序堆叠。成员操作区在窄屏换行。所有输入具有关联 Label、密码 autocomplete，错误用 Alert 宣告，复制失败提供手动选中链接；头像有文本回退，选择图片的按钮可通过键盘操作。对话框使用已有焦点管理和标题语义。

手机底部为路书、路线、助手、账户四项固定通栏导航，贴住屏幕底部，基础高度 64px，另计底部安全区域。内容两侧至少留出 16px 并尊重左右安全区域，按钮位于 iPhone Home 指示条上方，每项触控高度至少 48px。普通页面底部按导航总高度加 16px 预留空间；地图和助手的固定视口预留导航总高度，地图控件、表单末尾和聊天输入区不进入导航覆盖区域。桌面继续使用顶部导航。

## 8. 数据与接口映射

Session.adminConfigured → 管理配置状态；Session.user.role → 管理页或成员路书；Session → 登录门面；AccountUser → 本人资料和成员列表；Invite → 邀请摘要。接口与权限以同目录《账户系统》的接口表和 scripts/accounts.mjs 为准。身份来源为服务器 HttpOnly Cookie，不接受客户端传入的角色。

## 9. 实现边界与验收

当前为单个共同路书的成员账户，不含多空间管理、角色提升、共享聊天或可编辑路书数据库。正常注册、保存资料、登出、密码恢复必须可用；并发邀请消费、权限绕过、密码修改后旧会话、数据库重开均有服务端测试。桌面和手机的实际浏览器交互、PWA 真机账户行为需单独验证。
