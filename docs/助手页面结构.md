# 助手页面结构

本文面向前端维护者，用于在现有路书主题中维护助手的组件结构、响应式布局和状态。模式为设计并实现，保留既有暖白、砖红色、字体及圆角变量。

## 成员页面

```text
既有主导航：路书 / 路线 / 助手 / 账户
┌ 北行助手                                记忆 [Button] ┐
├──────────────────────────────────────────────────────┤
│ Conversation + ConversationContent      │ 记忆面板   │
│   发言者 Avatar / 名字                  │ 共同维护   │
│   Message / MessageContent              │ 可滚动条目 │
│   MessageResponse                       │ Textarea   │
│   {ToolCalls} 默认收起的处理过程         │ 保存按钮   │
│   ConversationScrollButton              │            │
├─────────────────────────────────────────┤            │
│ Notice                                 │            │
│ PromptInput / PromptInputTextarea        │            │
│ SpeechInput（麦克风） / PromptInputSubmit│            │
└──────────────────────────────────────────────────────┘
```

标题与输入区不参与聊天滚动。宽屏记忆面板在右侧；760px 以下占据聊天工作区，关闭后回到原对话。手机底部使用贴底的四项固定通栏导航，导航内部计入底部安全区域；助手容器预留导航总高度，输入框始终位于导航之上。较矮窗口压缩输入框高度。消息上方只显示账户头像与名字。

气泡按当前登录身份区分：自己的消息为米色，其他旅伴为浅绿色，助手保持原有样式。麦克风位于输入区右下角、发送按钮左侧，复用 InputGroupButton；录音时显示时长、结束与取消，识别时显示进度及取消，整组操作靠右排列。录音或识别期间禁用发送，完成后追加到草稿。切到后台或离开页面取消录音；重新连接提示放在输入框上方。

消息和工具来自服务端 SSE 快照，发言者与权限从登录会话确定。所有成员共用一个频道，进入页面建立 SSE、离开关闭；快照按版本合并，避免旧请求覆盖新回复。未配置模型禁止提交并提示管理员配置；流断开显示重连状态；失败保留草稿，可重试；工具输出可折叠，停止仅向本次发起者开放。记忆正在读取、为空、保存失败和协作更新均有对应状态。

## 管理页面

在已有成员管理下复用 Card、Field、Input、Checkbox、Button、Notice 增加模型与 MCP 配置。所有成员均可编辑和删除记忆，条目展示记录者及最近更新者。模型表单宽屏两列、手机一列；MCP 按服务显示配置卡片与发现的工具列表。密钥使用 password 输入框，读取配置时只提供已保存状态。环境管理的字段禁用；MCP 测试和保存过程禁用重复操作。

模型与 MCP 之间提供火山语音配置，默认显示新版 API Key，旧版 App ID 与 Access Token 放在可展开区域。保存复用统一按钮，字段按已有断点从双列切换为单列。

## 工具过程折叠

模式：修订并实现。面向聊天页面维护者，让成员先阅读回复，需要时再查看工具细节。

| 已确认项目事实 | 结构影响 |
| --- | --- |
| Vinext/React，客户端助手通过 SSE 读取 ChatSnapshot | 只调整展示，不改后端执行或消息协议 |
| shadcn base-nova / Base UI，Tailwind 4、Lucide | 使用现有 Collapsible 与 AI Elements Tool，保持路书主题 |
| chat-screen.tsx 已使用 Conversation、MessageResponse 和 Tool | 抽出 AssistantParts，保留正文、提示和工具详情 |
| 项目扫描 summary、routes --query agent、shell、components --query agent；CLI docs collapsible 与 search @shadcn -q collapsible 已核对 | 确认沿用助手页面和主导航；没有新页面或依赖 |

```text
[MessageContent]
  [MessageResponse 正文 / 说明]
  {ToolCalls}
    [CollapsibleTrigger > 处理过程 · 已处理 · 6 项工具] (默认收起)
    [CollapsibleContent] (展开后)
      [Tool > 读取路书 · 已完成]
        [ToolContent 参数 / 结果] (再次展开)
      [Tool > 查询天气 · 已完成]
      ...
  [MessageResponse 正文回复]
  [output 停止或错误提示]
```

同一条助手消息的工具集中在第一次工具出现的位置，内部按调用顺序展示；后续工具不重复占据顶层空间。所有正文和服务提示仍在外层显示，按原先正文之间的顺序排列。

- 初始状态始终收起，包括历史消息和正在执行的新消息；新增工具、结果返回与执行结束都不重置用户的展开选择。
- 收起时显示状态和调用总数；失败数量在外层可见。执行停止、中断或失败时不继续显示忙碌动画。不展示没有可靠来源的耗时。
- 没有工具的消息不渲染折叠栏，纯文本仍直接显示。
- 每个工具继续复用 ToolHeader、ToolContent、ToolInput、ToolOutput，内层默认收起。
- 手机与桌面使用相同层级；外层标题保持紧凑，长工具名省略，展开后的列表限制高度并允许滚动，参数与结果延用现有滚动区域。
- 触发器使用原生按钮语义和 aria-expanded，支持键盘 Enter/Space；展开区域可聚焦并滚动。展开仅是本地界面操作，不重新调用工具。
- 数据来自 ChatMessage.parts 中的 tool 项和 ChatMessage.status；工具状态使用既有 input-available、output-available、output-error。不新增接口或权限差异。

组件依据：[shadcn Collapsible](https://ui.shadcn.com/docs/components/base/collapsible)、[Base UI Collapsible](https://base-ui.com/react/components/collapsible)、[AI Elements Tool](https://elements.ai-sdk.dev/components/tool)。
