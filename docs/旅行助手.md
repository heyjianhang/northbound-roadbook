# 旅行助手

本文面向使用路书的旅伴、配置服务的管理员及后续维护者，用于开始聊天、管理记忆、接入模型和 MCP，并了解当前实现的边界。

## 旅伴使用

用普通成员账号登录，从导航进入“助手”。所有旅伴在同一个对话里和助手交流，消息显示各自名字，助手回复实时同步。记录保存在服务端，换设备或重新打开仍可继续。界面展示最近 200 条消息，每次回复带上最近 40 条已保存的消息；更早记录保留在数据库中，长期偏好通过共同记忆检索。

每场对话一次处理一个回复，处理中显示工具状态；其他旅伴可看进度，等回复结束再发送。发起者可以停止自己的回复。关闭页面不会主动停止服务端任务，再打开会同步当前进度；服务重启会将未完成回复标记为中断，需要重新发送问题。

可以先问“今天的行程怎么安排”，助手会读取 `data/roadbook.json` 中的实际路书。接入查询 MCP 后可查天气、地点等信息；可以按要求创建或编辑地点共同笔记；当前不会改动每日行程、发布帖子、下单或预订。

自己的消息使用米色气泡，其他旅伴的消息使用浅绿色气泡，头像旁保留发送者名字。

### 语音输入

点击输入框右下角、发送按钮左侧的麦克风，允许录音后开始说话，再次点击结束并识别。每次最多 60 秒，到时自动结束；文字追加到当前草稿，可以修改后再发送。识别中可以取消，离开页面或切到后台会取消语音输入并释放麦克风。录音和识别失败不会清空原有草稿。

语音输入需要 HTTPS（本机 localhost / 127.0.0.1 除外）和麦克风权限，安装 PWA 后仍需授权。局域网 HTTP 地址无法录音。语音录制结束后才请求识别，当前没有边说边显示文字或语音回复。

## 记忆规则

所有旅伴和助手使用同一个旅行记忆库。在聊天中明确说“请记住…”会让助手调用 LangMem 的记忆管理工具；也可以打开“记忆”面板直接添加、编辑和删除条目。每个人都能修改共同记忆，界面保留最初记录者和最近更新者，在线面板自动同步变化。

记忆中的个人偏好需要明确写出成员名字，例如“健航喜欢清淡口味”，不能将一个人的偏好当作全员约定。记录者和更新者从登录会话取得，浏览器不能伪造。

长期记忆使用 LangMem 的 `create_manage_memory_tool` 和 `create_search_memory_tool`，存储适配 LangGraph BaseStore，SQLite 持久化。工具仅可访问当前旅行的共同空间，不接受模型传入身份或切换到其他记忆空间。LangMem 不会把每一句聊天自动当作事实；当前采用对话内工具记录，未开启后台自动提取。

未填向量模型时按关键词（含中文字符）检索；填写后，使用 OpenAI 兼容 Embeddings 接口计算向量并按余弦相似度检索，旧记忆在检索时补建索引。这里的 RAG 是检索相关记忆供回复使用，尚未接入文档上传或知识库爬取。删除记忆只删除长期记忆条目，不会删除原聊天和运行检查点；最近对话里仍提到的内容可能继续影响回答。

## 管理员配置

管理账号用于配置，不参加成员聊天。登录后在“旅行助手”填写：

1. 模型接口地址，例如服务商给出的 `https://example.com/v1`，不包含 `/chat/completions`。
2. 模型名：服务商的模型 ID，需要支持工具调用和流式 Chat Completions。
3. API Key：保存在服务端，再次打开只显示“已保存”；留空保留旧值。
4. 向量模型：可选，需与对话模型共用接口地址、密钥，支持 Embeddings。

保存后下一次回复使用新配置，无需重启。非空环境变量 `AGENT_BASE_URL`、`AGENT_MODEL`、`AGENT_API_KEY`、`AGENT_EMBEDDING_MODEL` 优先于页面配置，对应页面字段不可编辑；修改环境变量后重启。模型未配置时，页面说明原因并禁止发送，不返回模拟回答。

配置与聊天、记忆都在默认 `.runtime/agent/`，不要放入 `public/`、提交到 Git 或打包进静态产物。该目录按服务端私有文件管理，配置密钥与数据库备份应一起保管。

### 火山语音配置

在豆包语音控制台开通“录音文件识别极速版”（资源 ID `volc.bigasr.auc_turbo`），然后在管理页面“旅行助手 → 火山语音识别”配置并保存：

- 新版控制台：填写语音 API Key。
- 旧版控制台：展开“旧版控制台凭据”，填写 App ID 和 Access Token。

同时配置时优先使用新版 API Key。语音凭据独立于 OpenAI 兼容的对话模型接口，留空保留已保存的凭据，接口不会返回密钥原文。保存后在线成员会收到新的可用状态，无需重启。

也可配置 `VOLC_SPEECH_API_KEY`，或 `VOLC_SPEECH_APP_ID` 与 `VOLC_SPEECH_ACCESS_TOKEN`。非空环境变量覆盖对应的管理页面字段，修改后重启服务。

实现使用官方[大模型录音文件极速版识别 API](https://www.volcengine.com/docs/6561/1631584?lang=zh)：浏览器将录音转成单声道、16 kHz、16-bit PCM WAV，经已登录的同源 `/api/agent/speech` 上传；服务端使用固定火山接口识别，仅向当前请求者返回文字。音频在本应用中仅驻留内存、不写入数据库或共同记忆；火山侧的数据处理以服务商设置和条款为准。点击发送后的文字才进入共同对话。

服务端校验音频格式和 60 秒时长上限，每位成员同时只允许一次识别、全站最多四次，火山请求最长 45 秒。可用状态仅表示凭据已配置，服务是否开通、额度和真实识别效果需首次录音验证。

## 地点共同笔记

进入任意地点，在封面下切换“帖子 / 笔记”。帖子保留现有收录链接；笔记是一份所有旅伴共同编辑的 Markdown 文档，支持标题、列表、表格、代码和链接。点击“写笔记”或“编辑”，在编辑和预览之间切换，最后保存。原始 HTML 不会作为页面代码执行。

同名地点在不同日期共用笔记，例如四次经过海拉尔时看到的是同一份内容。笔记标签可见时每 5 秒检查更新，回到窗口时也会刷新。切换帖子和笔记保留本页面内的草稿；保存失败也会保留草稿。离开地点前应保存编辑内容。

多人或 Agent 同时编辑时，服务端检查版本。遇到冲突，先复制草稿、查看并载入最新笔记，再合并保存；不能使用旧版本覆盖已保存的修改。最近编辑者显示实际发起修改的成员，Agent 代写归属于发起该轮对话的成员。

可以直接对助手说：“把想吃手把肉写到海拉尔的笔记里”或“把海拉尔笔记里的九点出发改成十点”。内置笔记 MCP 自动可用，无需第三方 API Key，也不依赖外部 MCP 网关。它通过固定 stdio 入口运行，提供以下工具：

| 工具 | 用途 |
|---|---|
| `notes_list_place_notes` | 按地点、日期或正文查找笔记摘要和真实地点 ID |
| `notes_read_place_note` | 读取完整 Markdown 和版本 |
| `notes_write_place_note` | 创建或保存完整文档，要求版本一致 |
| `notes_edit_place_note` | 精确替换唯一的一段文字，保留其他段落 |

笔记保存于 `AGENT_DATA_DIR/notes.sqlite`，应随整个助手目录备份。客户端和 Agent 共用同一套存储与版本检查。成员身份由服务器注入，不作为模型可修改的工具参数。这个 MCP 是应用内部服务，不提供面向外部客户端的公开入口。共同笔记独立于 LangMem 长期记忆，也不会自动变成每日行程。

## MCP 接入

管理员在“旅行助手 → MCP 服务”管理连接，普通旅伴直接在共同对话中使用。页面默认列出高德地图与天气、智谱联网搜索、当地美食推荐、飞猪旅行；新部署不会自带商家账户或密钥。

远程服务支持 SSE、Streamable HTTP、Bearer Token 和自定义请求头。点击“导入”可粘贴 `mcpServers` JSON，`streamableHttp` 会自动转换为内部连接类型，Markdown 包装的 URL 也会自动提取。导入只更新 MCP 配置，之后测试连接、勾选工具、启用并保存。密钥保存在服务端 SQLite，界面只显示是否已配置。留空保留原密钥；更换地址或连接类型会清除原目标的凭据和工具选择。

高德需要填写自己的服务实例地址。智谱和美食服务预置服务地址，需要填入对应服务的 Bearer Token，并先在提供方开通服务。连接状态和工具列表会持久保存；测试连接只进行初始化和工具发现，不执行业务查询。

助手只加载管理员选中的查询工具。服务声明 `readOnlyHint=true` 的工具可以选择；已核对用途的内置高德和美食查询工具也在固定白名单中。服务明确声明非只读时不会被白名单覆盖。中文或过长的工具名会转换为稳定的模型兼容名称，页面保留原名。单个服务连接失败时，其余查询仍可使用。

命令型 MCP 在服务端运行，手机和 PWA 不需要安装 Python 或 uv。当前只预留固定版本 `mcp-fliggy-travel==0.5.1` 的独立运行环境，不允许从管理页面执行任意命令。该包会向包作者的腾讯云代理转发飞猪凭据，因此飞猪入口在确认接入方式前保持不可用；此版本没有自动安装、启动该第三方包。OAuth 授权和任意 stdio 包的安装管理暂未实现。

## MCP 微服务部署

本地 `npm run dev` 和单容器部署默认按需启动独立 Python 网关进程，使用回环地址、动态端口和随机连接密钥。关闭路书服务时关闭网关。模型通过网关调用 MCP，MCP 工具参数和描述不会包含服务密钥。

独立容器部署使用仓库的 `compose.yaml`：

1. 按账户部署说明准备 `.env`，额外设置 `MCP_GATEWAY_TOKEN`，可以用 `openssl rand -hex 32` 生成。
2. 执行 `docker compose up -d --build`。路书监听本机 4173 端口，供反向代理访问；MCP 网关只在容器网络内监听，不发布宿主机端口。
3. 在管理页导入服务凭据、测试连接、选择工具并保存。

Compose 使用名为 `roadbook-data` 的持久化卷。迁移现有安装时先停止旧实例、备份整个 `.runtime` 并恢复到该卷；不要直接启动一个空卷后以为旧数据丢失。不要对同一 SQLite 目录运行多个路书实例。

已有独立网关时，在路书环境设置 `MCP_GATEWAY_URL` 和 `MCP_GATEWAY_TOKEN`，网关使用同一个连接密钥。跨主机部署时使用受保护的内网或 HTTPS。网关不保存账户、聊天和供应商密钥，只在请求处理期间使用后端传入的服务配置。未发布网关端口不影响它访问公网 MCP 服务。

## 维护与验证

Node 中间件复用账户会话、角色权限、同源写入校验和限流；聊天采用 SSE，同步快照在重连时恢复。Python worker 经 JSONL 管道接收服务端构造的身份和配置，不暴露独立接口、不读取管理员环境凭据。Deep Agents 使用默认的状态内虚拟文件系统，没有宿主机文件读取或 shell 执行权限。每次生成单独保存 LangGraph 检查点，失败运行不会把未完成的工具调用链带入下一次生成。

单个回复最多运行 240 秒、48 个图步骤，每个模型调用输出最多 4096 token，全站最多同时处理 4 场对话。当前采用单进程协调，不能水平扩容多个 Node 实例。聊天、记忆、检查点目前不自动过期；备份和数据清理按服务端部署管理。

```sh
npm run typecheck
npm run lint
npm test
.venv/bin/python -m unittest agent.test_memory agent.test_notes -v
PYTHONPATH=. .venv/bin/python tests/mcp-runtime.py
node --test tests/agent-runtime.integration.mjs
npm run build
```

运行集成测试会启动本地模拟的 OpenAI 兼容服务和 MCP 服务，实际执行 Deep Agents 与 LangMem，覆盖流式回复、记忆保存和检索、重启持久化、共同记忆协作、身份校验和旧非共享记录隔离、MCP 工具发现和只读过滤；不消耗真实模型额度。真实模型、外部 MCP 和手机 PWA 仍需填入对应配置后验证。

语音测试使用模拟的火山 HTTP 响应，覆盖新旧鉴权、音频编码、凭据隐藏、接口权限、取消与草稿回填，不消耗真实语音额度。真实火山账号与手机麦克风尚需配置后在设备上验证。
